# 개발 일지

Dungeon Crawler를 바이브 코딩으로 만들어 온 과정을 라운드별로 정리한 문서입니다.
현재 게임 사양과 코드 구조는 [README.md](../README.md)를 보세요.

---

## 0. 방향 정하기

- 처음에는 언리얼로 시작하려 했으나, **유니티로 결정**.
  - 언리얼의 블루프린트·레벨은 바이너리라 AI가 직접 읽고 고칠 수 없고, C++ 컴파일이 느림.
  - 유니티는 C# 하나로 끝나고, 수정 → 확인 주기가 짧아 바이브 코딩에 유리.
- 장르는 후보(웨이브 서바이벌, 덱빌딩, 타워 디펜스 등) 중 **2D 턴제 로그라이크 던전**을 선택.
- 핵심 원칙: **씬에 아무것도 배치하지 않고 코드가 모든 것을 생성**한다.
  그래서 말로 요청한 변경이 에디터 작업 없이 바로 반영된다.

## 1. 첫 플레이 버전

- 방 + 복도 랜덤 던전, 시야(FOV)와 탐험 기록, 턴제 이동·전투.
- 몬스터 4종(쥐·고블린·오크·트롤), 체력 물약·검·방패, 경험치와 레벨 업, 계단으로 다음 층.
- 그래픽은 코드로 그린 단색 도형, HUD는 IMGUI(`OnGUI`).
- 검증: 배치 모드로 컴파일·윈도우 빌드 후, 빌드를 실행해 스크린샷으로 한글 UI와 맵 표시를 확인.

## 2. 1차 자율 개발 — 콘텐츠와 연출

**추가**
- 몬스터 4종 추가(박쥐·고블린 궁수·해골·암흑 마법사), 5층마다 보스(계단 봉인).
- 두루마리 3종(화염·순간이동·지도)과 숫자 키 인벤토리, 몬스터 아이템 드롭.
- 데미지 숫자, 치명타, 화면 흔들림, 코드로 합성한 효과음, 미니맵, 게임 오버 화면과 최고 기록.
- `GameManager`를 기능별 partial 파일로 분리, 수치는 `GameData.cs`로 모음.

**자동 테스트 도구**
- 혼자 탐험·전투·아이템 사용·계단 이동을 하는 **자동 플레이 봇**을 만듦.
- `-autoshot`(장면별 스크린샷), `-simulate`(여러 판 통계) 실행 인자와 `Tools/build.ps1`, `Tools/test.ps1`.

**밸런스**
- 첫 시뮬레이션: 초반에 25%가 4~5층에서 죽고, 절반은 30층 넘게 생존 → 초반은 어렵고 후반은 너무 쉬움.
- 레벨 업 곡선을 가파르게, 몬스터 층별 강화를 크게 → 봇 평균 6.4층.

## 3. 2차 자율 개발 — 상점·특수 방·몬스터 행동

**추가**
- 골드와 상인/상점(보스 전 층에는 반드시 등장).
- 특수 방: 보물 창고, 제단(축복 또는 저주). 함정 3종(가시·경보·순간이동)과 함정 발견.
- 몬스터 행동: 도망(고블린), 동료 부르기, 거리 벌리기(궁수), 분열(슬라임, 신규), 격노(오크), 소환(강령술사, 신규), 배회.

**밸런스**
- 첫 시뮬레이션에서 경제가 무너짐: 골드 수천, 방어력 40 이상 → `공격 − 방어` 공식 때문에 사실상 무적.
- **피해 공식을 비율식으로 변경**(`공격 × 10 / (10 + 방어)`), 골드·물약 드롭 축소, 상점 가격 인상 → 봇 평균 25층에서 12.5층.
- 함정 때문에 봇이 계단으로 못 가는 문제 → 함정을 피하되 다른 길이 없으면 지나가도록 수정.

## 4. 3차 자율 개발 — 직업·장비·보스 패턴

**추가**
- 직업 선택 화면과 직업 3종(전사·도적·마법사), X 키 직업 스킬과 특성.
- 장비 3칸(무기·갑옷·반지), 등급 3단계, 특수 옵션 7종(흡혈·가시·재생 등). 자동 착용과 판매, 상점에서 장비 비교.
- 능력치를 "기본 + 장비"로 다시 계산하는 구조로 변경.
- 보스 패턴: 체력 단계별 소환, 예고 후 범위 내려찍기, 순간이동, 광폭화.

**밸런스**
- 장비가 들어가면서 다시 쉬워짐(평균 20.4층) → 장비 수치와 마법 화살 약화, 보스 체력·공격 대폭 상향 → 평균 14층대.
- 보스전 로그(`[BOSS]`)를 남겨 확인해 보니, 봇은 층을 다 정리하고 레벨이 높은 상태로 보스에 도착 → 보스는 "죽이지는 못해도 크게 소모시키는" 관문으로 둠.

## 5. 픽셀아트와 공격 모션 (사용자 요청)

- 직업 3종 + 몬스터 10종 + 보스 4종, 총 17종의 16×16 픽셀아트를 **글자 그림**으로 작성(`Art/PixelArt.cs`).
  직업 선택 화면에도 초상화 표시. `-gallery` 인자로 전체 그림을 한 화면에서 확인.
- 캐릭터 그림을 자식 오브젝트로 분리해, 실제 위치와 별개로 모션을 줌.
  - 공격: 뒤로 당김 → 앞으로 찌르기(늘어남) → 복귀, 대상에 베기 궤적.
  - 피격: 밀려남 + 붉게 번쩍. 이동: 깡총. 대기: 숨쉬기. 좌우 방향 전환.
  - 사망: 그림이 떠오르며 사라지고 픽셀 파편이 흩어짐. 회전베기·내려찍기 전용 연출.
- 카메라를 확대(한 칸 약 40px → 51px)해 픽셀아트가 잘 보이도록 함.
- **검은 화면 버그의 원인 발견**: 봇이 사람보다 훨씬 빨리 움직이면 그림이 실제 위치를 못 따라가고,
  카메라가 그림을 따라가면서 미탐험 영역이 보였음. 멀리 뒤처지면 더 빨리 따라잡도록 수정.

## 6. 자가 피드백 라운드

스크린샷 검토, 별도 에이전트의 코드 리뷰, 시뮬레이션 데이터로 스스로 문제를 찾아 고침.

**코드 리뷰로 찾은 버그 7건 (모두 수정)**
1. 광폭화한 보스가 내려찍기를 예고한 그 턴에 바로 실행 → 피할 수 없었음. 예고한 턴에는 실행하지 않도록 수정.
2. 마법 화살이 이미 사라진 소환수를 맞혀 처치·경험치가 중복 적용.
3. 함정으로 자기 턴에 죽어도 턴이 계속 진행되어 체력이 0 → 1로 회복되어 보임.
4. 떨어진 아이템이 플레이어·상인 발밑에 놓여 줍기 어렵거나 불가능.
5. 보스가 은신한 도적의 위치를 알고 부하를 소환, 소환 실패 시 단계가 소모됨.
6. 공격받는 중에도 꾹 누르던 이동이 계속됨 → 맞으면 멈추도록.
7. 직업 선택 화면에서 H 키가 전사 선택으로 처리됨. (덤으로 ㄹ 받침 뒤 '로/으로' 조사 처리도 보정)

**UI·연출 개선**
- 다친 몬스터 머리 위 체력 바, 데미지 숫자가 겹치지 않게 위로 쌓기.
- HUD 축소: 로그 패널을 작게, 조작법은 첫 계단 이후 자동으로 접고 Tab으로 열기.
- 받는 피해는 로그에 붉은색, 오래된 로그는 흐리게.
- 바닥 타일 변형(금·자갈·이끼)과 벽 횃불(일렁이는 빛).

**밸런스·기타**
- 물약이 너무 쌓임(봇 기준 5층에 20개) → 물약 드롭 확률 1/3 감소. 도적 기본 공격력 6 → 7.
- 테스트가 가끔 느려진 원인은 성능이 아니라 창이 포커스를 잃으면 유니티가 멈추는 기본 설정이었음 →
  `Run In Background` 켬. 실제 성능은 60fps, 턴 처리 약 1~2ms.
- 최종 시뮬레이션(60판): 전체 평균 13.5층 / 전사 15.9 · 마법사 12.7 · 도적 11.9.

## 7. 영구 성장 (사용자 요청)

- 런이 끝나면 도달 층·보스 처치·처치 수에 따라 **영혼석**을 얻고, 직업 선택 화면(U 키)에서 영구 강화 5종을 단계별로 구매.
  강인함(체력)·날카로움(공격)·단단함(방어)·비상 물약(시작 물약)·황금 손(골드 획득).
- 수치는 `GameData.MetaUpgrades`와 `SoulStonesFor`에 모으고, 화면·저장은 `GameManager.Meta.cs`로 분리. 저장은 `PlayerPrefs`.
- 봇·시뮬레이션에는 강화를 적용하지 않음 → 기존 밸런스 통계와 그대로 비교 가능.
- `-autoshot`이 강화 화면도 `_meta.png`로 저장.
