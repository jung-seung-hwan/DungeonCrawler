# 개발 일지

DungeonTamheomga(처음 이름은 Dungeon Crawler)를 바이브 코딩으로 만들어 온 과정을 라운드별로 정리한 문서입니다.
현재 게임 사양과 코드 구조는 [README.md](../README.md)를 보세요.

---

## 0. 방향 정하기

- 처음에는 언리얼로 시작하려 했으나, **유니티로 결정**.
  - 언리얼의 블루프린트·레벨은 바이너리라 AI가 직접 읽고 고칠 수 없고, C++ 컴파일이 느림.
  - 유니티는 C# 하나로 끝나고, 수정 → 확인 주기가 짧아 바이브 코딩에 유리.
- 장르는 후보(웨이브 서바이벌, 덱빌딩, 타워 디펜스 등) 중 **2D 턴제 로그라이크 던전**을 선택.
- 핵심 원칙: **씬에 아무것도 배치하지 않고 코드가 모든 것을 생성**한다.
  그래서 말로 요청한 변경이 에디터 작업 없이 바로 반영된다.

## 1. 첫 플레이 버전

- 방 + 복도 랜덤 던전, 시야(FOV)와 탐험 기록, 턴제 이동·전투.
- 몬스터 4종(쥐·고블린·오크·트롤), 체력 물약·검·방패, 경험치와 레벨 업, 계단으로 다음 층.
- 그래픽은 코드로 그린 단색 도형, HUD는 IMGUI(`OnGUI`).
- 검증: 배치 모드로 컴파일·윈도우 빌드 후, 빌드를 실행해 스크린샷으로 한글 UI와 맵 표시를 확인.

## 2. 1차 자율 개발 — 콘텐츠와 연출

**추가**
- 몬스터 4종 추가(박쥐·고블린 궁수·해골·암흑 마법사), 5층마다 보스(계단 봉인).
- 두루마리 3종(화염·순간이동·지도)과 숫자 키 인벤토리, 몬스터 아이템 드롭.
- 데미지 숫자, 치명타, 화면 흔들림, 코드로 합성한 효과음, 미니맵, 게임 오버 화면과 최고 기록.
- `GameManager`를 기능별 partial 파일로 분리, 수치는 `GameData.cs`로 모음.

**자동 테스트 도구**
- 혼자 탐험·전투·아이템 사용·계단 이동을 하는 **자동 플레이 봇**을 만듦.
- `-autoshot`(장면별 스크린샷), `-simulate`(여러 판 통계) 실행 인자와 `Tools/build.ps1`, `Tools/test.ps1`.

**밸런스**
- 첫 시뮬레이션: 초반에 25%가 4~5층에서 죽고, 절반은 30층 넘게 생존 → 초반은 어렵고 후반은 너무 쉬움.
- 레벨 업 곡선을 가파르게, 몬스터 층별 강화를 크게 → 봇 평균 6.4층.

## 3. 2차 자율 개발 — 상점·특수 방·몬스터 행동

**추가**
- 골드와 상인/상점(보스 전 층에는 반드시 등장).
- 특수 방: 보물 창고, 제단(축복 또는 저주). 함정 3종(가시·경보·순간이동)과 함정 발견.
- 몬스터 행동: 도망(고블린), 동료 부르기, 거리 벌리기(궁수), 분열(슬라임, 신규), 격노(오크), 소환(강령술사, 신규), 배회.

**밸런스**
- 첫 시뮬레이션에서 경제가 무너짐: 골드 수천, 방어력 40 이상 → `공격 − 방어` 공식 때문에 사실상 무적.
- **피해 공식을 비율식으로 변경**(`공격 × 10 / (10 + 방어)`), 골드·물약 드롭 축소, 상점 가격 인상 → 봇 평균 25층에서 12.5층.
- 함정 때문에 봇이 계단으로 못 가는 문제 → 함정을 피하되 다른 길이 없으면 지나가도록 수정.

## 4. 3차 자율 개발 — 직업·장비·보스 패턴

**추가**
- 직업 선택 화면과 직업 3종(전사·도적·마법사), X 키 직업 스킬과 특성.
- 장비 3칸(무기·갑옷·반지), 등급 3단계, 특수 옵션 7종(흡혈·가시·재생 등). 자동 착용과 판매, 상점에서 장비 비교.
- 능력치를 "기본 + 장비"로 다시 계산하는 구조로 변경.
- 보스 패턴: 체력 단계별 소환, 예고 후 범위 내려찍기, 순간이동, 광폭화.

**밸런스**
- 장비가 들어가면서 다시 쉬워짐(평균 20.4층) → 장비 수치와 마법 화살 약화, 보스 체력·공격 대폭 상향 → 평균 14층대.
- 보스전 로그(`[BOSS]`)를 남겨 확인해 보니, 봇은 층을 다 정리하고 레벨이 높은 상태로 보스에 도착 → 보스는 "죽이지는 못해도 크게 소모시키는" 관문으로 둠.

## 5. 픽셀아트와 공격 모션 (사용자 요청)

- 직업 3종 + 몬스터 10종 + 보스 4종, 총 17종의 16×16 픽셀아트를 **글자 그림**으로 작성(`Art/PixelArt.cs`).
  직업 선택 화면에도 초상화 표시. `-gallery` 인자로 전체 그림을 한 화면에서 확인.
- 캐릭터 그림을 자식 오브젝트로 분리해, 실제 위치와 별개로 모션을 줌.
  - 공격: 뒤로 당김 → 앞으로 찌르기(늘어남) → 복귀, 대상에 베기 궤적.
  - 피격: 밀려남 + 붉게 번쩍. 이동: 깡총. 대기: 숨쉬기. 좌우 방향 전환.
  - 사망: 그림이 떠오르며 사라지고 픽셀 파편이 흩어짐. 회전베기·내려찍기 전용 연출.
- 카메라를 확대(한 칸 약 40px → 51px)해 픽셀아트가 잘 보이도록 함.
- **검은 화면 버그의 원인 발견**: 봇이 사람보다 훨씬 빨리 움직이면 그림이 실제 위치를 못 따라가고,
  카메라가 그림을 따라가면서 미탐험 영역이 보였음. 멀리 뒤처지면 더 빨리 따라잡도록 수정.

## 6. 자가 피드백 라운드

스크린샷 검토, 별도 에이전트의 코드 리뷰, 시뮬레이션 데이터로 스스로 문제를 찾아 고침.

**코드 리뷰로 찾은 버그 7건 (모두 수정)**
1. 광폭화한 보스가 내려찍기를 예고한 그 턴에 바로 실행 → 피할 수 없었음. 예고한 턴에는 실행하지 않도록 수정.
2. 마법 화살이 이미 사라진 소환수를 맞혀 처치·경험치가 중복 적용.
3. 함정으로 자기 턴에 죽어도 턴이 계속 진행되어 체력이 0 → 1로 회복되어 보임.
4. 떨어진 아이템이 플레이어·상인 발밑에 놓여 줍기 어렵거나 불가능.
5. 보스가 은신한 도적의 위치를 알고 부하를 소환, 소환 실패 시 단계가 소모됨.
6. 공격받는 중에도 꾹 누르던 이동이 계속됨 → 맞으면 멈추도록.
7. 직업 선택 화면에서 H 키가 전사 선택으로 처리됨. (덤으로 ㄹ 받침 뒤 '로/으로' 조사 처리도 보정)

**UI·연출 개선**
- 다친 몬스터 머리 위 체력 바, 데미지 숫자가 겹치지 않게 위로 쌓기.
- HUD 축소: 로그 패널을 작게, 조작법은 첫 계단 이후 자동으로 접고 Tab으로 열기.
- 받는 피해는 로그에 붉은색, 오래된 로그는 흐리게.
- 바닥 타일 변형(금·자갈·이끼)과 벽 횃불(일렁이는 빛).

**밸런스·기타**
- 물약이 너무 쌓임(봇 기준 5층에 20개) → 물약 드롭 확률 1/3 감소. 도적 기본 공격력 6 → 7.
- 테스트가 가끔 느려진 원인은 성능이 아니라 창이 포커스를 잃으면 유니티가 멈추는 기본 설정이었음 →
  `Run In Background` 켬. 실제 성능은 60fps, 턴 처리 약 1~2ms.
- 최종 시뮬레이션(60판): 전체 평균 13.5층 / 전사 15.9 · 마법사 12.7 · 도적 11.9.

## 7. 영구 성장 (사용자 요청)

- 런이 끝나면 도달 층·보스 처치·처치 수에 따라 **영혼석**을 얻고, 직업 선택 화면(U 키)에서 영구 강화 5종을 단계별로 구매.
  강인함(체력)·날카로움(공격)·단단함(방어)·비상 물약(시작 물약)·황금 손(골드 획득).
- 수치는 `GameData.MetaUpgrades`와 `SoulStonesFor`에 모으고, 화면·저장은 `GameManager.Meta.cs`로 분리. 저장은 `PlayerPrefs`.
- 봇·시뮬레이션에는 강화를 적용하지 않음 → 기존 밸런스 통계와 그대로 비교 가능.
- `-autoshot`이 강화 화면도 `_meta.png`로 저장.

## 8. 언어 선택과 영어 추가 (사용자 요청)

- 직업 선택 화면에서 L 키로 한국어 ↔ 영어 전환. 선택은 `PlayerPrefs`에 저장하고, 저장된 선택이 없으면 시스템 언어를 따름.
  런 도중에는 바꿀 수 없게 해서 로그와 장비 이름에 두 언어가 섞이지 않음.
- `Loc.cs` 추가: 현재 언어, `Loc.T(한국어, 영어)`, 문자열 쌍 `Txt`. 직업·강화·장비 이름은 `Txt`로, 문장은 호출 자리에서
  `Ko ? ... : ...`로 두 언어를 나란히 적음. 별도 번역 파일을 두지 않은 이유는 문장마다 끼워 넣는 값과 어순이 달라서
  한국어 문장 옆에 영어 문장이 있는 편이 고치기 쉽기 때문.
- 몬스터·직업의 한국어 이름은 내부 키로 그대로 유지(`PixelArt.Get`, `EnemyNamed`, 보스의 `PhaseSummon`). 표시 이름만 번역.
- 조사 처리(`Josa`)는 한국어 문장에서만 호출. 영어는 관사(`the`, `Loc.A`의 a/an)와 단·복수를 문장에서 처리.
- 영어는 글자 수가 늘어나므로 `FitLabel` 추가: 한 줄 글자가 영역보다 길면 글자 크기를 줄여 그림. 상태 패널·로그·상점에 적용.
  덕분에 한국어에서도 잘리던 긴 장비 줄이 다 보이게 됨. 떠오르는 글자 영역도 넓혀 긴 장비 이름이 한 줄로 나옴.
- 검증: `test.ps1 shot -Lang en` / `-Lang ko`로 두 언어 화면 확인, `test.ps1 sim -Lang en`·`-Lang ko` 각 30판 예외 없음.
  게임 오버 화면과 L 키 전환·저장은 봇으로 확인할 수 없어 사람 플레이 확인이 필요.

## 9. 사운드 다양화와 배경음악 (사용자 요청)

- 효과음을 11종에서 42종으로 늘림. 그동안 `Magic` 하나가 스킬·두루마리·제단·보스 소환·순간이동에, `Pickup`이 줍기와 구매에,
  `Shoot`이 화살과 경보 함정에 함께 쓰였는데, 사건마다 다른 소리로 나눔(회복, 순간이동, 지도, 금화, 장비, 구매, 거절,
  함정, 경보 종, 축복·저주, 보스 등장·처치, 내려찍기 예고·실행, 소환, 광폭화, 영구 강화, 화면 조작음 등).
  합성 도구로 `Notes`(짧은 가락), `Bell`(종소리), `Mix`(겹치기)를 추가.
- 배경음악 4곡을 코드로 합성(`MusicSynth.cs`): 직업 선택(느린 가단조), 일반 층(어둡고 잔잔한 라단조 — 낮은 베이스, 느린 아르페지오,
  드문 종소리, 멀리서 울리는 북), 보스 층(빠른 마단조, 북과 몰아치는 베이스), 게임 오버(한 번만 나오는 하강 가락).
  악보는 `"D4:4 A4:4"`처럼 글자로 적어 말로 요청한 수정을 바로 반영할 수 있게 함.
- 곡 전환은 사건마다 호출하지 않고, 매 프레임 "지금 상태에 어울리는 곡"(`DesiredTrack`)을 보고 다르면 서서히 바꾸는 방식.
  보스 음악은 보스가 살아 있는 동안만 나오고, 쓰러뜨리면 일반 층 음악으로 돌아옴.
- 곡 합성은 수십만~백만 샘플 계산이라 시작할 때 백그라운드 스레드에서 미리 해 두고, 끝난 곡만 메인 스레드에서 `AudioClip`으로 만듦.
- M 키 음소거, [ · ] 키 음량 10단계(`AudioListener.volume`), `PlayerPrefs` 저장. 바꾸면 미니맵 아래에 잠깐 표시, 음소거 중에는 계속 표시.
- 화면 없는 배치 모드(시뮬레이션)에서는 소리를 아예 만들지 않음.
- 검증: 빌드 성공, `test.ps1 sim` 예외 없음, `test.ps1 shot`(창 모드라 소리가 실제로 합성·재생됨) 예외 없음.
  **소리가 실제로 어떻게 들리는지는 자동으로 확인할 수 없어 사람이 들어 봐야 함.**

## 10. 기록 화면 (사용자 요청)

- 다른 사람과 겨루는 온라인 순위표는 Xbox 서비스 연동 부담이 커서 접고, 자기 기록만 보는 화면으로 정함.
- 직업 선택 화면에서 T 키로 열며, 누적 통계(플레이 횟수·총 처치·쓰러뜨린 보스), 직업별 최고 도달 층, 상위 10판(층·직업·레벨·처치·사인·날짜)을 보여 줌.
  "최근 10판"이 아니라 "상위 10판"으로 정함(층 → 레벨 → 처치 수 순, 같으면 최근 판이 위).
- 저장은 `PlayerPrefs`의 JSON 문자열 하나(`Records`, `JsonUtility`). 화면·저장은 `GameManager.Records.cs`로 분리.
  전체 최고 도달 층은 예전 `BestDepth` 값을 그대로 써서, 기존 플레이어의 최고 기록이 그대로 남음.
- 직업은 `PlayerClass` 이름으로, 사인은 `enemy:<몬스터 키>`·`trap:<함정 종류>` 키로 저장하고 그릴 때 번역 → 저장 당시 언어로 굳지 않음.
  이를 위해 `DealDamage`에 언어와 무관한 `sourceKey`를 추가.
- 봇·시뮬레이션은 기록을 남기지 않음. `-autoshot`은 실제 기록 화면(`_records.png`)과, 저장하지 않는 예시 자료로 열 판을 꽉 채운
  화면(`_records_sample.png`)을 함께 찍어 글자 넘침을 확인할 수 있게 함.
- 검증: 빌드, 두 언어 스크린샷, 시뮬레이션 전후로 저장값이 바뀌지 않음을 확인.
  **실제로 죽었을 때 저장되고 재실행 후에도 남는지는 봇이 기록을 남기지 않아 사람 플레이 확인이 필요.**

## 11. 최종 보스와 심층 난이도 (사용자 요청)

**정한 것**
- 5·10·15·20층은 원래 보스 4종 그대로. 25~45층은 그 4종이 색을 바꿔 차례로 반복, 50층에 최종 보스 **공허의 군주**.
  55~95층도 같은 순서가 이어지고 100층에 더 강해진 공허의 군주. 엔딩·축하 화면은 없고 끝없이 내려갈 수 있음.
- 최종 보스 전용 음악은 만들지 않고 기존 보스 곡을 씀.

**구현**
- 보스 배치와 능력치를 `GameData.BossFor(층)` 한 곳에서 정함. 반복 회차는 "그 층 기준 몬스터(트롤)의 능력치 × 비율"로 맞춰서,
  몬스터 공식을 고치면 보스도 함께 따라감. 이름 앞에 흉포한·저주받은·불멸의·태고의가 붙음.
- 색 변형은 그림을 새로 그리지 않고 `PixelArt.Get(이름, 색조 이동)`으로 팔레트의 색조만 돌려서 만듦(외곽선은 그대로).
- 공허의 군주: 16×16 그림 추가. 광선·순간이동·범위 3 내려찍기·광폭화에 더해, 체력 2/3·1/3에서 앞선 보스들의 **그림자**를 두 마리씩 부름.
  그림자는 보스 패턴 없이 일반 몬스터처럼 싸우는 축소판(보랏빛, 0.6배 크기)이고 주인이 쓰러지면 사라짐.
- 장비 단계의 상한(4단계)을 없앰. 5단계부터는 재질 이름(흑요석 … 공허의)이 붙고 그 뒤로는 +1, +2 …. 무기 공격력은 단계의 1.65제곱으로 추가 성장.
- 몬스터 층별 강화 공식을 `Actor.FromTemplate`에서 `GameData`로 옮기고(20층까지는 값이 그대로), 20층 이후 공격력 추가 성장을 넣음.
- 깊은 층에서 무의미해지던 것들을 보정: 자연 회복량(최대 체력 240부터 증가), 마법 화살·화염 두루마리(공격력을 따라감).
  셋 다 얕은 층에서는 예전 값과 같음.

**수치를 맞춘 과정**
1. 시뮬레이션에 층별 도착 시점 능력치(`[SIM] arrive`)를 남기게 해서, 1층에서 시작한 봇의 실제 성장 곡선을 먼저 봄.
2. 그 결과 `-startdepth` 근사가 틀려 있었음: 레벨이 실제보다 낮고(20층에서 15 대 18.5), 물약을 3개만 줬는데 실제 봇은 10층에 약 20개,
   20층에 약 10개를 들고 있었음. 그래서 10층에서 시작한 봇이 그 층에서 바로 죽었음. 경험치·제단 축복·장비(최근 3층 중 최고)·소모품·골드를
   실측치에 맞게 고침. 고친 뒤 10층 시작 봇은 평균 2.5층을 더 내려감(실제 봇은 10층 도착 후 약 3.5층).
3. 깊은 층은 "내려간 층 수"로는 차이가 안 보임 — 봇은 20층부터 어느 층에서 시작해도 첫 층에서 죽음. 대신 죽기 전 처치 수와,
   도착 능력치로 계산한 "몬스터 하나 잡는 타수 × 한 대에 잃는 체력"을 지표로 삼음.
4. 첫 시도(무기 제곱 성장 + 갑옷 체력도 제곱 + 등급 배율)는 45~55층이 20층보다 오히려 쉬웠음(처치 33~36 대 17).
   깊은 층은 전부 희귀 이상이 나와 등급 배율이 겹친 탓. 등급 배율과 체력 제곱 성장을 빼고 무기만 1.65제곱으로 낮춤.
5. 50층 이후는 처음에 체력·공격을 함께 키웠다가, 싸움만 길어지는 것을 피하려고 공격력만 키우는 쪽으로 바꿈(100층 기준 타수 24 → 15).
6. 보스는 봇이 살아서 도착하지 못해 볼 수 없었으므로 `-bossonly`(다른 몬스터를 치우고 보스전만) 옵션을 추가해 따로 확인.

**결과** (README "현재 밸런스"에 표)
- 1층 시작 60판 평균 13.6층·14.0층 — 이전과 같은 범위.
- 죽기 전 처치 수: 20층 20 → 30층 23 → 40층 14 → 50층 18 → 60층 12 → 75층 11 → 100층 8. 판마다 ±3 정도 흔들림.
- 보스전: 반복 보스는 원래 보스와 같은 수준(45전 45승, 물약 거의 안 씀). 50층 공허의 군주는 45전 45승·물약 4.8개,
  100층은 45전 23승·물약 9.4개.
- 10~100층 시작 시뮬레이션과 보스전 시뮬레이션 모두 예외 없음.

**한계**
- 전부 봇 기준의 상대 비교. 봇은 20층에서 이미 한계라서 "사람이 50층까지 갈 수 있는가"는 확인하지 못함. 사람 플레이로 보고 계수를 조정해야 함.
- 스크린샷으로 색 변형(갤러리, 25층·45층), 50층 최종 보스와 내려찍기 예고, 그림자 소환, 두 언어 표시를 확인. 소리와 실제 조작감은 확인하지 못함.

## 12. 타이틀 화면, 게임 이름 변경, 마우스로 직업 선택 (사용자 요청)

- 게임 이름을 **DungeonTamheomga**로 바꿈: 화면 제목, 창 제목(`productName`), 실행 파일(`Builds/Windows/DungeonTamheomga.exe`),
  문서. 저장소 폴더와 Git 원격 이름은 그대로 둠.
- **타이틀 화면**(`GameManager.Title.cs`): 게임을 켜면 제목·세 직업 그림·"아무 키나 누르거나 마우스를 클릭해 시작" 안내가 먼저 나옴.
  아무 키나 마우스 버튼으로 직업 선택 화면으로 넘어가고, L(언어)·M·[ ](소리)은 타이틀에서도 그대로 동작. 직업 선택 화면에서 Esc를 누르면 타이틀로 돌아감.
  게임 오버 뒤 R은 예전처럼 직업 선택 화면으로 바로 감. 음악은 직업 선택 곡을 그대로 씀.
- **직업 선택 커서**: 카드에 마우스를 올리면 커서(직업 색 테두리)가 그 카드로 옮겨가고, 클릭하면 그 직업으로 시작.
  숫자 키 1~3은 예전처럼 바로 시작하고, 덤으로 A·D(←·→)로 커서를 옮겨 Enter·Space로 시작할 수도 있음.
  마우스가 실제로 움직였을 때만 커서를 옮겨서, 가만히 둔 마우스가 키보드 커서를 되돌리지 않음.
  마우스 좌표는 HUD와 같은 가상 좌표(높이 720 기준)로 바꿔서 카드 영역(`ClassCardRect`)과 비교 — 그리기와 판정이 같은 함수를 씀.
- 봇 모드는 입력을 읽지 않고 `BeginRun`으로 바로 들어가므로 타이틀에 막히지 않음. `-autoshot`은 타이틀 화면(`_title.png`)도 찍음.
- **저장 위치가 바뀜**: `PlayerPrefs`는 레지스트리 `HKCU\Software\<회사 이름>\<게임 이름>`에 저장되므로, 이름을 바꾸면
  예전 키(`...\DefaultCompany\Dungeon Crawler`)의 최고 기록·영혼석·강화·기록 화면 자료·언어·음량이 새 이름의 게임에서는 보이지 않음.
  예전 값은 지워지지 않고 그대로 남아 있어, 키를 복사하면 이어 쓸 수 있음(README "실행 방법" 참고).
  스토어 출시 전에 회사 이름(`DefaultCompany`)을 바꾸면 같은 일이 한 번 더 생김.

## 13. 영구 성장 재조정과 마법 피해 (사용자 요청)

**요청**: 영구 성장이 별로 매력이 없어 보임. 마법사가 무기를 먹으면 스킬 피해가 오르는지 확인.

- **마법 피해**: 마법 화살은 `3 + 레벨 + 층`과 `공격력 × 0.75` 중 큰 값이라, 20층 전에는 무기를 바꿔도 피해가 그대로였음.
  장비로 오른 공격력의 절반을 기본 값에 항상 더하도록 고침(화염 두루마리도 같음).
- **영구 강화**: 전부 시작 수치 고정값이라 10층만 넘으면 묻혔고, 5층까지 가는 판에 영혼석 20개인데 전부 사려면 630개였음.
  기존 5종은 가격을 낮추고 단계를 늘림. 비율 강화 3종(숙련: 주는 피해, 수호: 받는 피해, 배움: 경험치)과
  부활(한 판에 한 번 되살아남)를 추가. 영혼석 획득량도 올림(`(층−1)×3 + 보스×10 + 처치÷5`).
- **확인**: 빌드 성공. 30판 시뮬레이션 평균 층은 전사 14.0 → 15.4, 도적 12.7 → 13.3, 마법사 11.5 → 13.4
  (직업당 10판이라 ±1~2층은 흔들림, 봇에는 영구 강화가 적용되지 않으므로 마법 피해 변경만 반영된 수치).
  영구 강화 화면은 스크린샷으로 9종이 한 화면에 들어오는 것을 확인.
- **확인하지 못한 것**: 강화를 실제로 사서 다음 판에 적용되는지, 부활이 발동하는 장면, 강화를 모두 산 상태의 난이도.

## 14. Microsoft Store 출시 준비 (사용자 요청)

**요청**: 이 게임을 Microsoft Store에 올리는 것을 도와 달라.

- **방식**: 공식 문서를 확인해 MSIX 패키지 제출을 골랐음 — 지금 빌드를 그대로 묶을 수 있고, 스토어가 무료로 서명·호스팅·업데이트를 맡음.
  EXE/MSI 제출은 유료 코드 서명 인증서와 직접 호스팅이 필요하고, GDK(MSIXVC) 경로는 Microsoft가 Win32 게임에 권장하지만 준비물이 많음. 비교와 근거 링크는 `docs/STORE.md`.
- **아이콘**: 다른 그림처럼 코드로 생성(`ProjectTools.GenerateAppIcon` — 전사 픽셀아트를 둥근 사각형 위에). 실행 파일 아이콘으로 지정.
- **도구**: `Tools\pack-store.ps1`(매니페스트 작성, 크기별 로고, `makepri`·`makeappx`로 `.msix` 생성), `Tools\store-assets.ps1`(스토어 로고·포스터, 1920×1080 스크린샷 한/영),
  `Tools\test.ps1 shot`에 `-Width`·`-Height` 추가. 버전을 `1.0.0`으로.
- **글**: 스토어 설명 초안(한/영), 개인정보 처리방침 초안, 계정 생성부터 제출까지의 단계 안내(`docs/STORE.md`).
- **확인**: 빌드 성공(실행 파일에 아이콘 반영), 자리표시자 값으로 `.msix` 생성 성공(32MB), 로고·포스터와 스크린샷 15장 생성(예외 0건).
- **확인하지 못한 것**: Partner Center가 이 패키지를 받아 주는지와 인증 통과 여부(계정 필요), 패키지로 설치된 상태에서의 실행(개발자 모드 필요), Windows App Certification Kit 검사.
  게시자·제품 ID는 Partner Center에서 받아 `Tools/store/store.config.json`에 넣어야 함.
- **이어서**: 이름 예약 완료(제품 종류 "MSIX 또는 PWA 앱"). 제품 ID를 `store.config.json`에 넣어 제출용 `.msix` 생성. 회사 이름을 `Zmark`로 바꾸고 이 PC의 기록을 새 저장 위치로 복사(직업 선택 화면에서 영혼석 47·최고 9층 확인).
- **개인정보**: 게임 코드에는 네트워크·수집 코드가 없지만 유니티 기본값(`submitAnalytics: 1`)으로 엔진이 익명 하드웨어 통계를 보낼 수 있었음.
  `submitAnalytics: 0`으로 끄고 `unityanalytics` 모듈을 뺌. 다시 빌드해 봇 플레이 동안 게임 프로세스의 외부 연결이 관찰되지 않는 것을 확인.
- **배운 점**: PowerShell 5.1은 BOM 없는 UTF-8 스크립트를 시스템 코드 페이지로 읽어서, 한글 주석 끝의 바이트가 줄바꿈을 삼켜 다음 줄이 주석에 먹히는 일이 있었음. 새 스크립트는 UTF-8 BOM으로 저장.

## 15. 대각선 벽 통과와 꾹 누르기 끊김 (사용자 버그 보고)

(14장은 스토어 출시 준비로, `feature/store-release` 브랜치에 있음.)

**보고**: "벽 너머에 있는데 대각선으로 적이 넘어올 수 있다", "키보드를 꾹 누를 때 계속 갈 때도 있고 끊길 때도 있다".

### 대각선과 벽 모서리
- **원인**: 대각선 이동·근접 공격·길 찾기가 모두 "도착 칸이 바닥인가"만 보고, 그 대각선 양옆의 두 칸은 보지 않았음.
  그래서 방 입구나 꺾인 복도에서 벽 모서리를 끼고 지나가거나 때릴 수 있었고, 벽 두 개가 대각선으로 맞닿은 틈으로도 넘어올 수 있었음.
  플레이어도 똑같이 할 수 있었음(같은 코드).
- **규칙**: 대각선은 **양옆 두 칸이 모두 뚫려 있을 때만** 가능(하나라도 벽이면 막힘). `DungeonMap.CanStep(from, to)` 하나로 모아
  플레이어 이동·공격(상인에게 말 걸기 포함), 몬스터의 근접 공격·이동·도망·무작위 이동, `Pathfinder`, 회전베기, 분열·소환·제단 저주가 몬스터를 놓는 칸,
  보스 순간이동 도착 칸, 봇이 함께 씀. "둘 다 벽일 때만 막기"로 하면 사용자가 본 장면(방 입구·복도 모서리)이 그대로 남아서 엄격한 쪽을 골랐음.
  복도는 폭 1칸의 ㄱ자라 직각으로는 항상 이어지므로 못 가는 곳은 생기지 않음(꺾이는 곳에서 한 걸음 더 걸릴 뿐).
- 원거리 공격·마법 화살·화염구는 시야를 따름(모서리 너머 보이는 적은 맞음). 다만 대각선으로만 맞닿은 두 벽 사이의 틈으로는
  그 너머 바닥이 보이지 않게 함(`HasLineOfSight`) — 방 구석의 벽 타일은 예전처럼 보임. 보스 내려찍기와 화염구 주변 피해는 범위 공격이라 그대로 둠.
- 막힌 대각선으로 가려 하면 턴을 쓰지 않고 "벽 모서리에 막혀…" 안내를 한 번만 띄움(`LogOnce`).
- 공허의 군주의 그림자가 두 칸 바깥에 나타날 때 벽 너머(옆 복도)에 생길 수 있던 것도 걸어서 닿는 칸만 고르도록 고침.

### 꾹 누르기
- **버그였던 것**
  1. 방향 키를 누른 채 다른 방향 키를 눌렀다 떼면, 처음 키를 계속 누르고 있어도 멈췄음(`InputReader`가 키 하나만 기억). → 누른 순서대로 쌓아 두고, 나중 키를 떼면 먼저 누르던 키로 이어 감.
  2. 다른 명령 키(물약·대기 등)와 같은 프레임에 누른 방향 키가 무시됨. → 다음 프레임에 눌린 것으로 처리.
  3. 모퉁이나 시야 끝에서 잠깐 가려졌다 다시 보인 몬스터가 매번 "나타났다!"로 이동을 끊음. → 3턴 안에 다시 보이면 알림·멈춤을 건너뜀(`RespotQuietTurns`).
  4. 층에 도착하자마자 보이는 몬스터는 반대로 "나타났다" 알림이 없었음(처음부터 보이는 상태로 만들어져서). → 숨긴 상태로 만들어 첫 시야에서 알림.
  5. 직업 선택 화면에서 누르고 있던 방향 키가 던전에 들어가자마자 이동이 됨. → 런 시작·새 층에서는 뗐다 눌러야 움직임.
- **의도된 멈춤**(예전부터 있던 것 + 이번에 맞춘 것): 새 몬스터 발견, 피해, 함정 발견, 특수 방 발견, 보스 내려찍기 예고, 상점 열기 /
  이번에 추가: 함정을 밟았을 때 전부(예전에는 가시만 — 순간이동 함정 뒤에 엉뚱한 곳을 계속 걸었음), 제단, 계단(봉인되지 않았을 때).
  멈춘 뒤에는 키를 뗐다가 다시 눌러야 움직임(예전과 같음, 6장의 "맞으면 멈추도록" 결정 유지).
- **알아볼 수 있게**: 멈추는 곳을 `GameManager.StopHeldMove` 하나로 모으고, 이동이 끊기면 머리 위에 노란 "!"를 띄움.
  막 누른 첫 걸음에서 멈춘 경우에는 키를 0.25초 넘게 계속 누르고 있을 때만 띄움(톡톡 눌러 싸울 때마다 뜨지 않게).

### 확인
- 봇 모드를 시작할 때 `[CHECK]` 자체 검사 두 가지를 돌림: 작은 지도 세 개로 모서리 상황 재현(이동·길 찾기·시야),
  가짜 키보드·가짜 시계로 `InputReader` 7가지 경우. 플레이 중에는 모든 한 칸 이동과 근접 공격이 규칙을 지켰는지 셈.
- 같은 빌드에서 규칙만 예전으로 되돌리는 임시 스위치로 60판씩 비교(스위치는 커밋하지 않음):
  새 규칙 평균 14.0층(전사 14.1 / 도적 12.6 / 마법사 15.2), 예전 규칙 평균 14.0층(15.0 / 12.2 / 14.9) — 난이도 차이 없음.
  예전 규칙에서는 모서리 자체 검사가 실패함(검사가 실제로 버그를 잡는다는 뜻). 새 규칙 60판에서 이동 123만 번·근접 공격 3.7만 번 위반 0건.
- 봇이 막히는 판: 새 규칙 60판 중 3판은 **보이지 않는 몬스터가 외길을 막고 있어** 봇이 계속 기다린 경우였음(막히면 `[SIM] stuck` 줄에 상황을 남기게 함).
  봇이 마지막에는 보이는 몬스터만 피해서 가도록 고침.
- **새 규칙의 부작용 하나를 막음**: 복도와 맞닿은 방 입구 칸에 함정이 놓이면, 예전에는 대각선으로 비켜 들어갈 수 있었지만 이제는 피할 길이 없음
  (순간이동 함정이면 그 입구로는 못 들어감). 그런 칸에는 함정을 놓지 않게 함(`IsRoomEntrance`).
  적도 길도 없는데 봇이 막힌 판(30판 중 1판)을 보고 추정한 원인이며, 그 판을 직접 재현해 확인하지는 못함. 고친 뒤 45판에서는 막힌 판 0건.
- 최종 코드: 빌드 성공, 45판 평균 14.7층(전사 15.1 / 도적 13.5 / 마법사 15.4), 예외 0건, 이동 98만 번·근접 공격 3.2만 번 위반 0건, 막힌 판 0건.
  `test.ps1 shot -Lang ko`도 통과(자체 검사 두 가지 통과, 화면 정상).
- **확인하지 못한 것**: 실제 키보드로 꾹 누르기(여러 키, 멈춤 뒤 다시 누르기, "!" 표시 모양), 사람이 플레이할 때 모서리 규칙의 느낌.

### 다른 AI로 교차 확인 (사용자 요청)
- Codex CLI(읽기 전용, 스크립트 사본만 전달)에 원인 분석과 수정 검토를 맡김. Gemini CLI는 로그인이 풀려 있어 쓰지 못함.
- 반영: 여러 방향 키 문제(내 분석과 일치), 다른 명령과 같은 프레임의 키 누락, 직업 선택 → 던전으로 넘어가는 키(수정 검토에서 지적).
- 반영하지 않음: "둘 다 벽일 때만 막기" 제안(위 이유), "순간이동 도착 칸의 함정·제단이 발동하지 않는다"(도착 칸은 함정이 없는 일반 바닥만 고르므로 해당 없음),
  "멈춘 뒤 다시 눌러야 하는 것은 버그"(의도된 동작으로 유지하고 표시를 추가).
- 사용자 판단으로 남김: 한 번 밟은 함정이 사라지지 않고 다시 밟으면 또 발동하는 것(지금은 발견된 함정을 피해 다니는 설계), 보스 내려찍기가 벽 너머 칸에도 닿는 것.
